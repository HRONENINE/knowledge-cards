# 知识卡片（knowledge-cards）

把一段内容提炼成 5~8 张知识卡片。两条底线：**每张卡片的信息都来自原文；卡片数量等于内容真正支撑的数量**。5~8 是目标区间，不是配额——内容只撑得起 3 张就输出 3 张，绝不为凑数注水。

## 工作流程

### 1. 获取内容

- 用户粘贴了文字 → 直接使用，进入第 2 步。
- 用户给了文件路径 → 用 Read 读取完整内容。仅支持 `.md` 和 `.txt`；其他格式如实告知暂不支持，不要强行解析。多个文件时逐个处理、分别输出各自的卡片。
- 两者都没有 → 请用户提供文章或文件路径。不要凭记忆对某本书或某篇文章生成卡片——那等于编造。

### 2. 通读全文，列出候选知识点

逐段自问：这段在教读者什么？删掉它读者会损失什么？

入选标准（满足其一即可）：
- 改变读者对一个主题的理解：概念、原理、机制
- 读者可以直接照做：方法、步骤、清单
- 反直觉的结论、关键数据、有信息量的案例

排除：过渡句、客套话、重复强调、营销话术、与主题无关的枝节。

### 3. 筛选与合并

- **一卡一点**：每张卡片只回答一个问题。一个主题下有多个子要点时，按子要点拆卡，而不是按段落机械切分。
- **去重**：同一观点在原文出现多次 → 只做一张卡片，把各处的补充细节合并进这张卡的"简明解释"。判断标准是"知识点是否相同"，不是"文字是否相同"。
- **择优截断**：候选点超过 8 个 → 只保留最重要的 8 个（最能改变理解或行为的优先），并在输出末尾注明"原文另有 N 个次要知识点，未展开"。
- 用户明确指定了卡片数量时以用户为准，但"一卡一点"与"不编造"仍然适用。

### 4. 撰写卡片

按下方格式撰写。每张写完即自检：信息是否只来自原文？是否只讲了一个点？自测问题是否仅凭原文可答？

### 5. 输出

- 卡片语言跟随原文语言。
- 在回复中完整展示全部卡片——这是用户阅读的主要途径，不要只给文件。
- 输入是本地文件时，另存为 Markdown：与源文件同目录，命名 `<原文件名>-知识卡片.md`。输入是粘贴文本时，默认只在回复中展示；用户要求存盘时，用文章标题做文件名。
- 卡片不足 5 张时，在输出开头用一句话说明原因（如"原文较短，仅提炼出 3 个独立知识点"），然后照常输出。

## 卡片格式

每张卡片固定四个字段：

```markdown
## 卡片 2 · 间隔重复比考前突击记得更牢

**核心知识**：把复习分散到多天，比集中在一天背诵记得更久。

**简明解释**：原文指出，遗忘最快发生在学习后的头 24 小时；在接近遗忘的时间点再次提取记忆，记忆痕迹会被重新加固。集中突击当时正确率高，但一周后大部分被遗忘。

**例子**：原文实验中，两组学生学习同样的 40 个单词，分散组在第 1、3、7 天各复习一次，一周后的测试成绩比集中组高约 40%。
```

此示例仅示意格式与详略程度；实际内容必须来自当前输入。

## 撰写细则

- **标题**：用能独立成意的完整判断句（"间隔重复比考前突击记得更牢"），不用空泛名词（"间隔重复""要点一"）。读者只看标题就该知道这张卡讲什么。
- **核心知识**：一句话，只写知识点本身，不带论证。
- **简明解释**：2~4 句，用自己的话把原文论述讲清楚，可保留原文的关键数据。原文的限定条件必须保留：原文说"仅在实验条件下成立"，卡片不能写成普遍结论。
- **例子或自测**：优先用原文自带的例子，标注「**例子**」；原文没有合适例子时写自测问题，标注「**自测**」，问题必须能仅凭原文回答，并在其后用一行给出参考答案要点。

## 红线

- **不编造**：原文没有的数据、结论、人名、术语、例子一律不写。"简明解释"只能重组原文已有信息，不得引入外部知识补全逻辑。
- **不注水**：不用"背景介绍""全文总结"之类的卡片凑数，不为拆而拆。
- **不抬高确定性**：原文说"可能""有研究认为"，卡片保持同样的语气。

## 输出前自检

- [ ] 每张卡独立可读，不依赖其他卡片
- [ ] 任意两张卡的核心知识不重复
- [ ] 每个事实都能在原文中找到依据
- [ ] 卡片数量等于内容真正支撑的数量（5~8 张，或更少且已说明原因）
